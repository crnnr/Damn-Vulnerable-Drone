    \subsection{Understanding Supply Chain Attacks}

    \begin{hintbox}
    \textbf{What is a Supply Chain Attack? (Simple Explanation)}

    Imagine ordering food at your favorite restaurant. You trust the restaurant completely, so you never question where the ingredients come from or if someone has tampered with them. 

    A \textbf{supply chain attack} is like secretly contaminating these ingredients at the supplier stage—before they ever reach the restaurant. By the time the ingredients are delivered, even the trusted restaurant unknowingly serves compromised meals to customers.

    In the cybersecurity world, hackers don't always directly target their primary victims. Instead, they inject malicious code into software or updates during their development phase. Once installed by the end-users, this software is already compromised.

    \textbf{Real-world examples include:}
    \begin{itemize}
        \item \textbf{SolarWinds (2020)} – attackers infiltrated software updates used by major companies and government agencies.
        \item \textbf{Codecov (2021)} – attackers altered CI/CD pipeline scripts, compromising customer data.
        \item \textbf{Multiple npm package compromises} – attackers planted malicious code within popular software libraries.
    \end{itemize}
    \end{hintbox}

    \section{Background: MITRE ATT\&CK Framework}

    \begin{hintbox}
    \textbf{What is the MITRE ATT\&CK Framework?}

    The MITRE ATT\&CK Framework is a globally recognized knowledge base of cyberattack techniques and tactics. It helps security professionals understand how real-world attackers operate, map their activities, and improve defenses.

    \textbf{Key Concepts:}
    \begin{itemize}
        \item \textbf{Tactics:} The attacker's goals (e.g., Initial Access, Persistence, Privilege Escalation)
        \item \textbf{Techniques:} How those goals are achieved (e.g., Phishing, Exploiting Vulnerabilities, Scheduled Tasks)
        \item \textbf{Procedures:} Real-world examples of how techniques are used
    \end{itemize}

    In this lab, you'll see MITRE IDs (like T1078) that map your actions to real attacker behaviors!
    \end{hintbox}

    \begin{hintbox}
    \textbf{Docker in a Nutshell}

    Docker is a tool that lets you run applications in isolated environments called \textbf{containers}. Think of containers as lightweight, portable virtual computers that always work the same way, no matter where you run them.

    \textbf{Why use Docker?}
    \begin{itemize}
        \item Easy to set up complex labs and environments
        \item Each container is separate and safe to experiment in
        \item Used by real companies for development and deployment
    \end{itemize}
    \end{hintbox}

    \section{Cronjobs}

    A common method of privilege escalation (both on Linux and Windows!) involves exploiting scheduled tasks. In Linux these are known as \textbf{cronjobs}. Cronjobs are automated tasks scheduled to run periodically under a defined user account.

    Let's investigate if there are any cronjobs configured on this system.

    \begin{lstlisting}[language=bash, caption=Checking cronjobs]
    # Check cronjobs belonging to your current user
    crontab -l

    # Check system-wide cronjobs (typically requiring higher privileges)
    ls -la /etc/cron*

    # View cronjob configuration files for scheduled tasks
    cat /etc/crontab
    cat /etc/cron.d/*
    \end{lstlisting}

    \begin{hintbox}
    \noindent
    \textbf{What do cronjobs look like?}

    \textbf{Cronjob Format:}
    Each line in a cronjob file follows this format:
    \begin{verbatim}
    * * * * * useraccount command-or-script-to-execute
    \end{verbatim}
    The five asterisks represent the schedule:
    \begin{itemize}
        \item \textbf{Minute} (0-59)
        \item \textbf{Hour} (0-23)
        \item \textbf{Day of Month} (1-31)
        \item \textbf{Month} (1-12)
        \item \textbf{Day of Week} (0-7, where both 0 and 7 represent Sunday)
    \end{itemize}
    For example, \texttt{0 5 * * 1 user1 /path/to/script.sh} runs the script every Monday at 5:00 AM in the user1's context.

    \end{hintbox}

    \subsection{Analyzing Cronjob Vulnerabilities}

    When analyzing cronjobs for vulnerabilities, look for the following common security issues:

    \begin{itemize}[itemsep=0.5em]
        \item Cronjobs running scripts from directories where you have write permissions.
        \item Scripts or binaries executed by cronjobs that lack absolute paths, making them susceptible to path manipulation.
        \item Cronjobs that execute scripts with overly permissive file permissions.
    \end{itemize}

    \newpage
    Consider the following example of a vulnerable cronjob:

    \begin{lstlisting}[language=bash, caption=Example vulnerable cronjob]
    # /etc/crontab
    * * * * * root /home/developer/scripts/backup.sh
    \end{lstlisting}

    This cronjob runs every minute as the \texttt{root} user, executing the script \texttt{backup.sh}. If the developer account has write permissions on this script or the containing directory, it provides a direct pathway to privilege escalation.

    \begin{warningbox}

    \subsection{The Privilege Escalation Hunt}

    \begin{hintbox}
    \textbf{What is sudo?}

    \texttt{sudo} stands for "Super User DO". It allows regular users to run specific commands as the root (administrator) user. 

    When you run \texttt{sudo -l}, you're asking: "What am I allowed to do as root?"

    If a system is misconfigured, you might find that you can run dangerous commands as root, even from a regular user account!
    \end{hintbox}

    \begin{challengebox}{Privilege Discovery}
    When you run \texttt{sudo -l} and find that you can run some commands without a password (look for "NOPASSWD"), you've found a critical security vulnerability! Write down the flag below:

    \texttt{FOUND\_SUDO\_PRIVILEGES}

    \subsection{Understanding Cron Jobs}

    Cron is like a robot assistant that runs commands automatically on a schedule:

    \begin{lstlisting}[language=bash, caption=Setting Up Malicious Cron Job]
    # Create a malicious cron job to trigger our supply chain attack
    sudo crontab -e

    # Add this line to run the build script every 2 minutes:
    # */2 * * * * /opt/build-update.sh

    # Verify the cron job was installed
    sudo crontab -l
    \end{lstlisting}

    \begin{hintbox}
    \textbf{How to Read Cron Syntax}

    A cron job looks like: \texttt{*/2 * * * * /opt/build-update.sh}

    The five stars represent:
    \begin{itemize}
        \item \texttt{*/2} = every 2 minutes
        \item \texttt{*} = every hour
        \item \texttt{*} = every day of month
        \item \texttt{*} = every month
        \item \texttt{*} = every day of week
    \end{itemize}

    So \texttt{*/2 * * * *} means "every 2 minutes"!
    \end{hintbox}
